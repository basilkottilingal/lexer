# Changelog

## v2.1

Fixes in the generated scanner, a faster scanner loop, `%option yylineno`,
and a scanning speed benchmark against flex.

**Upgrading:**

- **Regenerate your lexers.** Scanners generated by v2.0 can mis-tokenize
  inputs larger than their 16 kB buffer (#21), and `lxr_read_bytes ()`
  can crash on a token longer than the buffer (#22).
- **Line numbers are now off by default**, as in flex. Add
  `%option yylineno` (or define `LXR_YYLINENO`) if your actions use
  `yylineno` or `yycolno`; without it they stay at 1. With it, `yylineno`
  now follows flex: inside an action it already includes the newlines of
  the current token (v2.0 gave the line where the token starts).

### Bugs fixed

Found by the scanning speed benchmark (large inputs) and by building the
scanner with a tiny buffer (`-DLXR_BUFF_SIZE=7`).

| # | Where | Bug | Effect |
|---|---|---|---|
| 21 | `src/lxr/tokenize.c` | After a buffer refill, the scanner resumed from the state before the end-of-buffer transition but left it on the state stack. It was pushed again, so every older entry was paired with the wrong input position. | When the longest match had to back up across a refill, the token came out one byte short: `8%` was split into `8` and `%`, and `end` returned as `en`. When the token started before the refill, the length could go negative (heap overflow). With the default 16 kB buffer it was rare: 16 of 3.4 million tokens on a 4 MB random-lexer input, none in the C and JSON tests. |
| 22 | `src/lxr/source.c` `lxr_read_bytes` | The buffer's `size` was never set (uninitialized `malloc`), and `yytext[-1]` was uninitialized when `bol` = 0. | A token longer than the buffer made the scanner allocate a garbage size, or stop at once. |
| 23 | `Makefile` | The dependency on `stringified.h` was declared for `obj/lxr.o`, which doesn't exist; the real object is `obj/lex.o`. | Edits to `src/lxr/*.c` didn't reach the `lxr` binary until a clean build. |
| 24 | `src/lxr/tokenize.c` | A pattern with the end-of-line anchor (`abc$`) was taken only when another, earlier pattern also matched at the same place. | `abc$` on its own never matched. |

### Faster scanners

Generated scanners, flex 2.6.4 for comparison, 32 MB inputs in memory,
`gcc -O2` (`make bench` in `test/comparison`):

| Lexer | lxr / flex `-Cem` time, v2.0 | v2.1 |
|---|---:|---:|
| `c99.lex` on C source | 1.12 | **0.92** |
| `json.lex` on JSON | 1.41 | **1.19** |
| 3 random lexers | 0.86 – 1.11 | **0.79 – 1.01** |

Below 1 means lxr is faster. Where it came from:

- Line tracking off by default (see Upgrading): about 14% on C and JSON.
- New scanner loop: like flex, it remembers the last accepting state
  while it reads, instead of pushing every state on a stack and scanning
  it backwards. At the end of the buffer it refills and goes on from the
  same state. Also simpler (the stack resume logic of bugs #21 / #22 is
  gone), and without the old 128-state stack.

flex's full tables (`-8 -Cf`) are still 1.5 – 2.5× faster than lxr.

### Other changes

- `%option` is parsed. `%option yylineno` turns on line tracking.
  Options that don't affect lxr (`noyywrap`, `nounput`, `noinput`,
  `8bit`, ...) are accepted silently; others, and directives like `%x` or
  `%top`, get a warning that names them. (Before, every `%` line gave
  "unknown/unimplemented".)
- `yylineno` matches flex, including newlines read with `lxr_input ()`
  (and `lxr_unput ()` of a newline decrements it). Checked against flex
  on 4.9 million tokens of C.
- `$` keeps lxr's meaning, which differs from flex in two ways: it also
  matches at end of file, and it is not trailing context (with `abc` and
  then `abc$`, the earlier rule wins for `abc\n`; flex counts the `\n`
  in the match length and prefers `abc$`). Now documented in the README.
- `languages/test/lexer.lex` used `lxr_line_no` / `lxr_col_no`, which
  don't exist; it now uses `yylineno` / `yycolno`.
- `test/comparison/`:
  - new `bench.py` (`make bench`): scanning speed of lxr vs flex
    (`-Cem`, `-Ce`, `-8 -Cf`) on C, JSON and random lexers, checking that
    all scanners produce the same tokens;
  - `compare.py` also builds every lxr scanner with a 7-byte buffer, so
    that buffer refills are tested inside almost every token
    (`DIFF(buf7)` in the report).

## v2.0

Bug-fix release for the lexer generator (`lxr`), plus a table size
comparison against flex (see [README](README.md#comparison-with-flex)).

**Upgrading:** regenerate your lexers. Scanners generated by v1.0 can
mis-tokenize. With the keyword-merging bug (#19), a keyword of three or
more characters accepted *any* first character, so the JSON lexer read
`xrue` as `true`.

Tables are also smaller. Bogus equivalence classes are gone (#3), and
DFA minimization is now correct (#19).

### Wrong scanners (correctness)

| # | Where | Bug | Example |
|---|---|---|---|
| 19 | `dfa.c` `hopcroft` | Hopcroft's worklist started with the accepting blocks only. That is valid only for a *complete* DFA; lxr's DFA leaves missing transitions to an implicit dead state, so distinguishable states were merged. | With `abc` and `.`, the input `xbc` was lexed as `abc`. `json.lex` lexed `xrue`, `nalse` and `xull` as keywords. |
| 18 | `lex.c` `_pattern` | A quoted string was not one unit: a quantifier after it applied to its last character only. | `"ab"?` meant `ab?`; it now means `(ab)?`, as in flex. |
| 13 | `regex.c` `rgx_rpn` | The optional BOL wrapper `^?( … )` was skipped when a pattern started with `(`. | `(a)\|b` became `^?(a)\|b`, so `b` at the start of a line was not matched. |
| 14 | `lex.c` `_pattern` | Spaces (and tabs) inside quotes were not escaped, and a space ends a regex. | `"a b"` failed to parse. |
| 20 | `lex.c` `macro_new` | Quoted strings in macro definitions were not handled, and `{` / `"` inside `[...]` were taken as a macro / quote. | `M "a+b"` and `M [{]` were rejected. |
| 15 | `lex.c` definitions | A block comment ending in `**/` never closed. | `/* comment **/` |
| 3 | `nfa.c` `nfa_reset` | The counts in `x{m,n}` were taken as characters, which created bogus equivalence classes (see also the memory-safety table). | `{4}` gave `\x04` its own class. |

### Crashes and memory safety

| # | Where | Bug | Trigger |
|---|---|---|---|
| 1 | `dfa.c` `dfa_root` | The bit-set stack was created before its size was computed (64 B default), so a heap overflow happened with more than 512 NFA states. | `languages/c99/c99.lex` |
| 2 | `dfa.c`, `compression.c` | `base`/`accept`/`def` had `m` entries but state ids go up to `m`, so `[m]` was written out of bounds. | Small lexers (1, 3 or 5 rules) |
| 3 | `nfa.c` `nfa_reset` | Quantifier counts were used as character indices: `csingle[4096] = 1`, a stack overflow. | `a{4096}` |
| 4 | `nfa.c`, `dfa.c` | On error `nfa_reset` returned before setting the class table, and no caller checked, so a NULL class table was dereferenced. A full 256-character range was wrongly an error. | `[\x00-\xff]` |
| 5 | `nfa.c` `states_add`, `dfa.c` `hopcroft` | The ε-closure marked a state visited only *after* descending, so ε-cycles looped until out of memory. Then a NULL root DFA was dereferenced (`!nfa` was checked instead of `!root`). | `a**`, `(a*)*` |
| 6 | `dfa.c` `dfa_root` | The `primes[]` table was read past its end for more than 16384 NFA states, giving a garbage hash size (SIGFPE). | `((a{100}){100}){2}b` |
| 7 | `lex.c` `macro_new` | `rgx[rpnlen]` was written before checking `rpnlen <= 0`, a stack write at `rgx[-10]`. | Macro `M a)` |
| 8 | `lex.c` `_pattern` | The buffer limit check (`len == lim-2`) was skipped when 2 bytes were added at once, a stack overflow. | Long quoted pattern |
| 9 | `regex.c` `rgx_rpn` | `"^?(" + rgx + ")"` needs `len+5` bytes; the buffer had `len+4`. | 256-character regex |
| 10 | `regex.c` `rgx_token` | An unterminated `{` read past the end of the string. | `^a{3` |
| 11 | `regex.c` | `charclass` state was not reset per regex, so an unclosed `[` corrupted the next rule. | `[abc` followed by another rule |
| 12 | `nfa.h`, `class.h` | Class ids of 256 and up collide with the NFA's ε/accept ids, and the limit was checked too late. | 252 or more single-byte rules |
| 16 | `dfa.c` | `"%s"` was given `rgx` (`char **`) instead of `rgx[i]`, printing garbage error messages. | Any rule that fails NFA creation |
| 17 | `stack.c` `stack_cmp` | Only whole 8-byte words were compared; the trailing bytes of the bit set were skipped. | (found in review) |
| — | `allocator.c` | `assert (s <= PAGE_SIZE)`: any allocation over 8 kB aborted (e.g. an ε-closure of more than 1024 NFA states). | 40% of random 5–40 rule lexers |
| — | `lex.c` `lex_read_rules` | An "rgx buffer limit" error (`RGXOOM`) was ignored and parsing went on with a truncated rule. | Very long pattern |

### Other changes

- Table limit raised from one page (2048 entries) to `SHRT_MAX` (the
  generated tables are `short`); there is a new error if the number of
  states doesn't fit.
- Clear error messages instead of crashes for: reversed ranges (`[z-a]`),
  unterminated `[` / `{` / quoted macro strings, repetition counts over 255,
  more than 256 equivalence classes, too-large quantifier expansions, and
  zero-length tokens (`a**`).
- New `test/comparison/`: table-size comparison with flex on random
  lexers, which also checks that both scanners produce the same tokens.
